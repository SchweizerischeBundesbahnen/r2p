# R²P Console — Design System & Brand Reference

> ⚠️ **LLM-generated document.** This reference was generated by an LLM (Claude) from the
> R²P Brand Guidelines, the R²P WebClient source, and the Console implementation. Treat it as
> a working aid, not a hand-authored spec — verify against the actual code in `style.css` and
> the WebClient before relying on any detail, and correct it when it drifts.

> **Purpose.** This is the authoritative reference for the look & feel of the R²P Console
> (the Spring Boot server UI in `src/main/resources/static`). Read it **before** adding or
> changing any UI, so extensions stay on-brand and consistent. It distills the official
> *R²P Brand Guidelines v1.0* and mirrors the refreshed R²P WebClient (the Angular sibling
> app at `../r2p-webclient`). When in doubt, match the WebClient and these tokens.

The UI is **static HTML + [Alpine.js](https://alpinejs.dev/) + vanilla CSS** — no Thymeleaf,
no build step for the frontend. Everything visual is driven by CSS custom properties in one
stylesheet, so most of the brand lives in tokens + a handful of component classes.

---

## 1. Brand in one minute

- **Vendor-neutral.** R²P serves *all* railway undertakings (EVU). The chrome must **never**
  look like SBB or any single operator. Per-operator colour appears **only** in small partner
  badges — never in the app chrome.
- **Palette:** dark **Navy** + a single vibrant **Orange** + neutrals on airy **light-grey** surfaces.
- **Orange is a signal colour**, used sparingly: primary button fills, the 2px rule under the
  top bar, active/selected states, count badges, active sort glyph, the logo's `²`.
  **Never orange text on white/light-grey.** Orange text is only allowed **on navy**.
- **Flat.** No drop shadows, no gradients, no glow. Separate with 1px borders and the
  navy/grey/white value structure. (The only `box-shadow` allowed is the orange focus ring.)
- **Restrained symbols.** **No decorative emojis** (no 🚂💾📋👁️⚙️🌿🔀🔍⚠️✓). A plain `+` for
  add-actions; functional glyphs (sort `⇅`/`↑`/`↓`, chevrons, copy/view as short text) are fine.
- **Sentence case** for headings and labels ("Traffic overview", not "Traffic Overview").
- Always write **R²P** with the superscript ² (e.g. in `<title>` use the literal `R²P`),
  never "R2P" or "R^2P". The product name is **R²P Console**; the top-bar wordmark is **"Console"**.
- **Language:** the Console is **English-only** (the WebClient is bilingual EN/DE; the Console
  intentionally is not). Keep new copy in sentence-case English.

## 2. Where the design lives

| Concern | Location |
|---|---|
| All tokens + component CSS | `src/main/resources/static/style.css` |
| Logo / app mark / favicon | `src/main/resources/static/img/r2p-mark.svg` (the isolated navy square mark; used in the top bar **and** as `<link rel="icon">`) |
| Roboto font (self-hosted) | `src/main/resources/static/fonts/roboto-latin-{400,500,700}-normal.woff2` — the **exact `@fontsource/roboto` files the WebClient uses**, so stroke weight matches 1:1. Wired via `@font-face` at the top of `style.css`. No web-font/CDN/webjar dependency. |
| Pages | `index.html` (traffic overview), `details.html` (train details), `train-version.html` (JSON viewer) |
| Shared JS helpers (badges, sorter, formatting) | `static/js/r2p-utils.js` |

> **Maven note:** `*.html` under `static/` is resource-**filtered** (so `@project.version@`
> is substituted into the version pill). Non-HTML assets (CSS, SVG, fonts) are copied
> unfiltered — so don't put `@…@` tokens in CSS.

## 3. Colour tokens (use the CSS variables, never raw hex)

Defined in `:root` in `style.css`. Brand layer:

| Token | Hex | Use |
|---|---|---|
| `--navy` | `#0D1B2A` | top-bar/wordmark, headings, body text on light, table headers, logo field |
| `--orange` | `#F47B20` | accent: CTA fills, top-bar hairline, active states, count badges, active sort glyph, logo ² |
| `--orange-hover` | `#E06D14` | CTA hover |
| `--steel` | `#8AAFC8` | secondary text on dark, dividers, inactive sort glyph, decorative (large/low-contrast only) |
| `--teal` | `#3D6880` | secondary/tertiary text & **links on light**, field/section labels, accent borders |
| `--white` | `#FFFFFF` | surfaces, cards, top bar |
| `--light-grey` | `#F4F6F8` | page background, even table rows, subtle fills |
| `--border` | `#CCCCCC` | table/row borders |
| `--border-soft` | `#E2E8F0` | card/input/hairline borders |

Text aliases: `--text-primary` (navy), `--text-secondary` (teal), `--text-muted` (steel —
large/decorative only, below AA for small text on white).

**Functional (non-brand) colours — meaning, not chrome.** Keep these for their semantics:

- **Branch/MR state & changelog action badges:** accessible tinted *pills* (green/blue/amber/red/purple
  families) defined as `--status-*` / `--action-*` tokens. Each pill carries a **leading dot + text label**
  (never colour alone).
- **Partner colours** (`--partner-sbb`, `--partner-bls`, …): scoped to `.partner-badge` only.

**Hard rules:** orange text only on navy · no orange table row/cell backgrounds · no shadows/gradients/glow ·
the logo sits only on navy or white.

## 4. Typography

- **Family:** `'Roboto', 'Segoe UI', system-ui, sans-serif` (set on `body`). Roboto is self-hosted
  (see §2); Segoe UI/system-ui is the graceful fallback.
- **Weights:** 400 body, 500 medium, 700 headings/labels. Line-height ~1.5.
- **Headings:** `h1` = 1.375rem / 700 / letter-spacing −0.3px; `h2` = 1.25rem / 700; `h3` = 1.05rem / 600.
  All **sentence case**.
- **Micro-labels** (`.eyebrow`, `.detail-label`, `.field`/filter labels, table headers): 0.6875rem,
  700, UPPERCASE, letter-spacing ~0.06–0.08em, colour `--teal`.
- **Code / identifiers / JSON:** `'Courier New', monospace`.

## 5. Spacing & radii

Spacing scale (`--spacing-xs…2xl` = 0.25/0.5/1/1.5/2/3 rem). Radii: `--radius-sm` 4px (partner badges),
`--radius-md` 6px (inputs, small buttons), `--radius-lg` 8px (buttons, tables), `--radius-xl` 10px
(cards, modals), `--radius-pill` 999px (badges, count badges, status pills).

**Layout (matches the WebClient):** `html` sets `scrollbar-gutter: stable` (keeps a small, stable gap
on the right and stops overlays from shifting the layout). Do **not** add `-webkit-font-smoothing`
(it thins the text and diverges from the WebClient). The **top bar spans the full viewport width**
(`.topbar-inner`
has only `padding: 0 var(--spacing-xl)`, no max-width), so the logo sits one `--spacing-xl` from the
screen edge. **Page content is centred**: an outer `.main-content` carries `padding: var(--spacing-xl)`
and an inner `.container` is `max-width: 1400px; margin: 0 auto` (no padding of its own). On wide screens
the content therefore starts further in than the top-bar logo — this is intentional. Reuse this
`topbar (full-width) → main-content → container` structure on every page.

## 6. Components (class → spec)

- **Top bar** `.topbar` — white, sticky, 64px, 1px bottom border **plus a 2px orange hairline**
  (`.topbar::after`). Left: `.logo-tile` (the SVG mark, 34px) + `.wordmark` ("Console") + `.version-pill`
  (light-grey pill, holds `@project.version@`). Right (`.topbar-right`): org/instance badge and the
  PoC "Acting as" token selector (`.token-selector`). No shadow.
- **Prototype banner** `.poc-banner` — full-width band, background `#f5a623`, black centred text,
  bold `<strong>` emphasis. Sits above the top bar. (Mirrors the WebClient prototype banner.)
- **Page header** `.page-header` — `h1` on the left, actions on the right, vertically centred.
- **Breadcrumb** `.breadcrumb` — "Traffic overview › … › current"; earlier crumbs are teal links
  (`.breadcrumb a`), separators `.breadcrumb__sep` (steel), current `.breadcrumb__current` (muted).
  Use instead of a lone back-link on detail/sub pages.
- **Buttons** `.btn` + one of `.btn-primary` (orange fill — the only orange fill; one per view),
  `.btn-secondary` (white, navy border), `.btn-ghost` (white, soft border, teal text), `.btn-danger`
  (white, red border/text). `.button` (legacy) == primary; `.button-secondary` == secondary.
  Add-actions read `+ New …` (plain plus, sentence case). Focus ring = orange (the one allowed shadow).
- **Filters toggle** `.btn-filter` — compact (padding 8px 14px, 0.8125rem), white with navy border;
  contains an inline funnel SVG (`.funnel-icon`), the label, an orange `.filter-count` badge when filters
  are active, and a chevron (`▾` collapsed / `▴` expanded). Pressed/active state `.is-active` = navy fill,
  white text. Reveals the collapsible `.filter-bar`.
- **Cards** `.card` — white, 1px `--border` (#CCCCCC), radius `--radius-lg` (8px), `overflow:hidden`,
  **no shadow**, no padding of its own. Put content in a padded `.card-body`, or compose a **card with a
  header**: `.card > .card-header` (`.card-title`, 1rem/600) + flush content. **Section titles belong
  *inside* their card** as a `.card-header` (e.g. Merge requests / Branches / Changelog on the details
  page) — not as a free `<h2>` floating above a separate card. **Table sections** (Merge requests /
  Branches / Changelog) follow this shape: `.card > .card-header` (`.card-title` + a per-section **Filters
  toggle** `.btn-filter`, shown only when the section has data) over a padded `.card-body` that holds the
  **collapsible** `.filter-bar` (hidden by default, revealed by the toggle), the bordered `.table-container`
  (inset by the body padding — it must **not** run edge-to-edge), or an `.empty-state` hint. Each section
  has its own `…FiltersExpanded` flag + `…ActiveFilterCount` getter (mirroring the overview).
- **Detail identity header** (details.html "Train" card) — one `.card > .card-body` with a
  `.card-header-row` (`.eyebrow` "Train" + `h1.page-title` train number + `.page-subtitle` "Operational
  day: …" in muted `--text-muted` grey), a `.header-divider` (inset by the body padding — it must **not**
  reach the card edges), then an `.info-band` of `.info-item`s (`.info-label` micro-label + `.info-value`).
- **Info card / identity band** `.info-card` (see `details.html` "General information") — replaces grey
  tiles. `.info-card__head` (eyebrow label + big `.info-card__title` + `.info-card__sub`), a 1px
  `.info-card__divider`, then `.info-card__meta` with boxless `.meta-group` (micro-label above value).
  **Do not** revert to grey filled `.detail-item` tiles.
- **Statistics section** (overview) `.stats-section` — an `.eyebrow` ("Statistics") + per-partner
  `.stat-filter` in `.stats-section__head`, then `.statistics` cards (`.stat-card`, white, 1px border,
  3px orange left accent). A `<hr class="section-divider">` + a `Trains` `<h2>` clearly separate the
  statistics block from the table.
- **Data table** — navy `thead` (white, uppercase, letter-spaced micro-labels), `tbody` rows alternate
  white / `--light-grey`, 1px `--border` rows, neutral hover `#E9EDF1`. Clickable rows (`.clickable`)
  show a chevron that shifts + turns orange on hover. **Never** orange as a row/cell background.
- **Sort indicators** — a `.sort-indicator` span sits **inline right after** the header label and shows
  `⇅` when inactive, `↑`/`↓` when active (white, inheriting the header colour) — matching the WebClient.
  The glyphs come from `makeSorter().indicator()` in `r2p-utils.js` (`⇅` inactive → `↑`/`↓` active). Keep
  this scheme for any new sortable table; do not position the glyph absolutely at the cell's right edge.
- **Tooltip anchor** `.tooltip-anchor` (+ nested `.tooltip-box`) — a small **filled** steel circle with a
  white `?`, revealing a flat navy tooltip box on hover/focus. Use for legend/help affordances (e.g. the
  Status column) instead of the native `title` attribute.
- **Badges & pills** — `.badge` + a `badge-*` modifier = tinted pill with a leading dot (branch state /
  changelog action). `.partner-badge` + `.partner-badge-<OP>` = solid operator-coloured pill (the only
  operator colour). `.count-pill` (+`--mr`) = neutral count chips for open branches / merge requests.
  Class names map from `r2p-utils.js` (`partnerBadgeClass`, `branchStateBadgeClass`, `actionBadgeClass`,
  `mergeRequestBadgeClass`) — **preserve these class names** when changing styles.
- **Forms / filters** — labels **above** controls. `.filter-input` / `.filter-select`: white, 1px
  `--border-soft`, navy text, orange focus ring. The overview `.filter-bar` is **collapsible**
  (`x-show="filtersExpanded"`, collapsed by default) with an orange count badge driven by
  `activeFilterCount`.
- **Pagination** `.pagination-*` — white buttons, soft borders, navy text, orange focus ring.
- **States** — Loading: a quiet centred line. Empty: **never render an empty table** — hide the whole
  `.table-container` and show a standalone `.empty-state` instead (a faded steel `.empty-state-icon`, an
  `.empty-state-text` sentence, an `.empty-state-subtext` hint; `.empty-state-compact` for in-page
  sub-tables). No emoji. Error: `.alert-banner.alert-banner--error` (flat tinted, 1px border, text only).
  Toast `.toast`: flat navy. Gate these with `x-show` (+ `x-cloak`) on the filtered-list length.
- **JSON viewer** (`train-version.html`) — `pretty-json` themed with functional code colours (Courier);
  brand toolbar buttons `.toolbar-btn`.

## 7. Rules for extending the UI (LLM checklist)

When adding a page or component, keep it on-brand:

1. **Reuse tokens** — reference `var(--navy)`, `var(--orange)`, spacing/radii vars; never hard-code hex.
2. **Reuse the chrome** — every page gets the `.topbar` (logo mark + "Console" wordmark + version pill,
   inside the Alpine `x-data` scope so the token selector works), the `.poc-banner`, and the favicon
   `<link rel="icon" type="image/svg+xml" href="/img/r2p-mark.svg">`. `<title>` = `R²P Console — <context>`.
3. **Reuse components** — prefer existing classes (`.btn*`, `.card`, `.table-container`, `.badge*`,
   `.breadcrumb`, `.info-card`, `.filter-bar`) over new bespoke CSS.
4. **One orange primary per view.** Everything else is secondary/ghost. No orange text on light.
5. **Flat** — no shadows/gradients/glow; separate with 1px borders and value. (Orange focus ring is the
   only allowed shadow.)
6. **No decorative emoji.** Use the established glyphs (`+`, `⇅`/`↑`/`↓`, chevrons) or short text
   ("Copy", "View").
7. **Sentence case**, micro-labels for field/section labels, status as **shape/label + dot** (never
   colour alone), partner colour only inside `.partner-badge`.
8. **Preserve JS-facing class names** (the `*BadgeClass` mappings, `.sort-indicator`, `.active-sort`,
   `.clickable`) when restyling — the Alpine templates and `r2p-utils.js` depend on them.
9. **English-only**, write **R²P** with the superscript ².
10. **Match the WebClient** (`../r2p-webclient`, esp. `src/styles.scss` and the
    `traffic-overview` / `layout` components) when a pattern already exists there.
