= REST Endpoints

All endpoints are under the `/v1` path prefix. See also: link:../src/main/resources/openapi/r2p-spec.yaml[r2p-spec.yaml]

All endpoints require a `token` header parameter containing the partner's authentication token.

== Train Management

=== List Trains
* *GET* `/v1/trains`
* *Query Parameters:*
  - `operationalDayFrom` (optional): Filter for trains from this date (inclusive)
  - `operationalDayTo` (optional): Filter for trains up to this date (inclusive)
* *Description:* Returns all trains accessible to the partner, showing all branches with their latest version
* *Response:* Array of `TrainListElement` objects containing trainId, partners, branches, and main branch timestamp

=== Create Train
* *POST* `/v1/trains`
* *Query Parameters:*
  - `comment` (required): Description of the train creation
* *Request Body:* `Train` object (JSON)
* *Description:* Creates a new train with the given payload. **Only the Lead RU can create trains.** Automatically creates a main branch owned by the Lead RU. The train is initially only accessible to the Lead RU until explicitly shared.
* *Response:* `TrainListElement` with the newly created train information

=== Get Train by ID
* *GET* `/v1/trains/\{trainId}`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
* *Description:* Returns detailed information about a specific train, including all branches and their latest versions
* *Response:* `TrainListElement` object

=== Share Train
* *POST* `/v1/trains/\{trainId}/share`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
* *Query Parameters:*
  - `shareWith` (required): Partner name to share the train with
* *Description:* Grants access to the train for another partner. Only the Lead RU or partners who already have access can share the train.
* *Response:* Updated `TrainListElement`

=== Unshare Train
* *POST* `/v1/trains/\{trainId}/unshare`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
* *Query Parameters:*
  - `unshareWith` (required): Partner name to revoke access from
* *Description:* Revokes train access from a partner. Lead RU can unshare with any partner; partners can unshare with themselves.
* *Response:* Updated `TrainListElement`

== Branch Management

=== Create Branch
* *POST* `/v1/trains/\{trainId}/branches`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
* *Query Parameters:*
  - `branchName` (required): Name for the new branch (max 255 chars)
  - `comment` (required): Description of why the branch is created
* *Request Body:* `Train` object (JSON) with the proposed changes
* *Description:* Creates a new branch for proposing changes to the train. Both the Lead RU and shared partners can create branches. The branch is owned by the authenticated partner and starts in state `OPEN`.
* *Response:* `Branch` object with business and technical data

=== Get Branch
* *GET* `/v1/trains/\{trainId}/branches/\{branchId}`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
  - `branchId` (UUID): The branch identifier
* *Description:* Returns detailed information about a specific branch
* *Response:* `Branch` object

=== Update Branch
* *PUT* `/v1/trains/\{trainId}/branches/\{branchId}`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
  - `branchId` (UUID): The branch identifier
* *Query Parameters:*
  - `comment` (required): Description of the changes
* *Request Body:* `Train` object (JSON) with updated data
* *Description:* Creates a new version of the branch with the provided train data. Partners can only update their own branches; the Lead RU can update any branch including main. Not allowed when a branch is in `MERGE_REQUESTED`, `MERGED`, or `DELETED` state.
* *Response:* Updated `Branch` object

=== Delete Branch
* *DELETE* `/v1/trains/\{trainId}/branches/\{branchId}`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
  - `branchId` (UUID): The branch identifier
* *Query Parameters:*
  - `comment` (required): Reason for deletion
* *Description:* Marks a branch as deleted. The main branch cannot be deleted. Partners can only delete their own branches; the Lead RU can delete any partner branch.
* *Response:* `Branch` object with state set to `DELETED`

== Merge Request Workflow

The merge request workflow allows shared partners to propose that their branch changes be merged into the main branch by the Lead RU.

=== List Merge Requests
* *GET* `/v1/trains/\{trainId}/mergeRequests`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
* *Query Parameters:*
  - `state` (optional): Filter by merge action (`merge_requested`, `merge_rejected`, `merged`)
* *Description:* Returns the latest merge-related changelog entry per branch for the given train. Actions covered are `MERGE_REQUESTED`, `MERGE_REJECTED`, and `MERGED`. For every branch that has at least one such entry, the most recent entry is returned.
* *Response:* Array of `Change` objects

=== Request Merge
* *POST* `/v1/trains/\{trainId}/branches/\{branchId}/requestMerge`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
  - `branchId` (UUID): The branch identifier
* *Query Parameters:*
  - `comment` (optional): Reason or description for the merge request
* *Description:* Creates a merge request for a branch to be merged into the main branch. **Only the branch owner can create a merge request.** The branch state changes to `MERGE_REQUESTED`. The merge request becomes visible to the Lead RU via the list merge requests endpoint.
* *Response:* Updated `Branch` object

=== Merge Branch into Main
* *POST* `/v1/trains/\{trainId}/branches/\{branchId}/merge`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
  - `branchId` (UUID): The branch identifier
* *Query Parameters:*
  - `reviewedVersion` (required): The version UUID that the Lead RU has reviewed; must match the current head version of the branch
  - `comment` (optional): Comment for the merge
* *Description:* Merges the current state of a branch into the main branch. **Only the Lead RU can perform a merge.** The `reviewedVersion` acts as a safety check — if the branch has been modified since the Lead RU reviewed it, the merge is rejected with a conflict error. The branch state changes to `MERGED` and the main branch is updated with the branch content.
* *Response:* Updated `TrainListElement` reflecting the new main branch version

=== Reject Merge Request
* *POST* `/v1/trains/\{trainId}/branches/\{branchId}/rejectMerge`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
  - `branchId` (UUID): The branch identifier
* *Query Parameters:*
  - `comment` (optional): Reason for rejection
* *Description:* Rejects an open merge request. **Only the Lead RU can reject a merge request.** The branch state reverts to `OPEN`, and the rejection is recorded in the changelog. The branch data remains unchanged and the partner can continue working on it.
* *Response:* Updated `Branch` object

== Version Management

=== Get Specific Version
* *GET* `/v1/trains/versions/\{version}`
* *Path Parameters:*
  - `version` (UUID): The specific version identifier
* *Description:* Returns the train data for a specific version. The trainId is implied by the version.
* *Response:* `Train` object (JSON)

== Change Log

=== Get Train Changes
* *GET* `/v1/trains/\{trainId}/changes`
* *Path Parameters:*
  - `trainId` (UUID): The train identifier
* *Query Parameters:*
  - `from` (optional): Timestamp to filter changes from (inclusive)
  - `to` (optional): Timestamp to filter changes to (inclusive)
* *Description:* Returns all changes (creates, updates, shares, merges, etc.) for a specific train
* *Response:* Array of `Change` objects

=== List All Changes
* *GET* `/v1/trains/changes`
* *Query Parameters:*
  - `from` (required): Timestamp to filter changes from (inclusive)
  - `to` (required): Timestamp to filter changes to (inclusive)
* *Description:* Returns all changes for all trains accessible to the partner
* *Response:* Array of `Change` objects

== Response Models

=== TrainListElement
Contains: `trainId`, `mainTimestamp`, `partners` (array of partner names), `branches` (array of Branch objects)

=== Branch
Contains: `branchId`, `branchName`, `business` (BranchBusinessData), `technical` (BranchTechnicalData)

* *BranchBusinessData:* `trainNumber`, `operationalDay`
* *BranchTechnicalData:* `version`, `timestamp`, `comment`, `owner`, `branchState`, `mainBranch`

=== Change
Contains: `action`, `partner`, `affectedPartner`, `trainId`, `branchId`, `branchName`, `version`, `timestamp`, `comment`

=== BranchState
Possible values: `open`, `merge_requested`, `merged`, `deleted`

=== Action (Change log actions)
Possible values: `created`, `updated`, `merge_requested`, `merge_rejected`, `merged`, `deleted`, `shared`, `unshared`
